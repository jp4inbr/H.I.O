# 4. Documento de Requisitos

## Requisitos Funcionais (RF)

<details>

<summary><strong>RF01. Autenticação e Perfis</strong> </summary>

O sistema deve oferecer login com usuário e senha e diferenciar dois perfis:

* **Operador:** executa rotinas, consulta o histórico e altera a própria senha.
* **Administrador:** faz o mesmo que o Operador e também gerencia usuários.&#x20;

{% hint style="info" %}
**Aceite:** um usuário não autenticado não acessa nenhuma tela além do login.
{% endhint %}

</details>

<details>

<summary><strong>RF02. Painel de Rotinas</strong> </summary>

O sistema deve exibir as rotinas disponíveis em cards, cada um com nome e descrição curta.&#x20;

{% hint style="info" %}
**Aceite:** toda rotina cadastrada no backend aparece no painel sem alteração no frontend.
{% endhint %}

</details>

<details>

<summary><strong>RF03. Envio e Validação de Entrada</strong> </summary>

O sistema deve permitir o envio de um ou mais arquivos por arrastar e soltar ou por seleção. O formato e os campos obrigatórios devem ser validados conforme o contrato do módulo antes da execução. Cada módulo deve oferecer o download do seu arquivo modelo de entrada.&#x20;

{% hint style="info" %}
**Aceite:** um arquivo inválido é recusado com uma mensagem que diz o que está errado e como corrigir (ex.: "Falta a coluna Ponto. Baixe o arquivo modelo para ver o formato esperado.").
{% endhint %}

</details>

<details>

<summary><strong>RF04. Pré-visualização da Entrada</strong></summary>

Após o envio, o sistema deve exibir uma prévia para o usuário confirmar antes de executar:

* **Planilhas:** colunas e quantidade de anexos.
* **PDFs:** lista dos arquivos, com quantidade de anexos.&#x20;

Nessa etapa, o usuário pode remover ou trocar arquivos sem precisar recomeçar.

</details>

<details>

<summary><strong>RF05. Execução com Um Clique e Status</strong> </summary>

O sistema deve disparar a rotina com um único botão e exibir o status da execução durante o processamento:&#x20;

* Em execução
* Concluída
* Concluída com ressalva
* Falhou
* Cancelada

O usuário pode cancelar uma execução em andamento.

</details>

<details>

<summary><strong>RF06. Resultado e Download</strong> </summary>

Ao final, o sistema deve exibir o resultado nas três zonas do padrão de módulo:

1. **Resumo:** cards e alertas.
2. **Visualização principal** do módulo.
3. **Detalhe:** tabela completa, recolhida por padrão, com exportação para XLSX.&#x20;

Quando o módulo gerar textos (ex.: mensagens de agendamento), eles devem aparecer com botão de copiar.&#x20;

{% hint style="info" %}
**Aceite:** o usuário identifica o que exige ação sem abrir a tabela de detalhe.
{% endhint %}

</details>

<details>

<summary><strong>RF07. Histórico de Execuções</strong></summary>

O sistema deve registrar cada execução com:

* Usuário
* Rotina
* Arquivo de entrada (nome)
* Data e hora
* Status
* Resumo estruturado

Os registros não podem ser editados pela interface. O histórico deve permitir baixar novamente o resultado das execuções recentes.

</details>

<details>

<summary><strong>RF08. Informe de IA</strong> </summary>

O sistema deve gerar, sob demanda, um informe curto e objetivo a partir dos resumos estruturados das últimas execuções. O informe deve apontar:

* Falhas
* Inconsistências recorrentes
* Rotinas com mais problemas

A IA apenas lê e resume esses dados. Ela não executa rotinas, não altera dados e não recebe os arquivos originais.

</details>

## Requisitos Não Funcionais (RNF)

<details>

<summary><strong>RNF01. Usabilidade</strong></summary>

O usuário deve executar cada rotina da forma mais intuitiva possível, com a complexidade abstraída e na menor quantidade de cliques possível. A interface segue as heurísticas de Nielsen, com as decisões de design justificadas por elas.&#x20;

{% hint style="info" %}
**Aceite (teste de usabilidade, baseado na ISO 9241-11):**

* **Eficácia:** um usuário sem treinamento conclui qualquer rotina sozinho, sem ajuda.
* **Eficiência:** a execução, do painel até o resultado, leva até 5 minutos (sem contar o tempo de processamento).
* **Satisfação:** nota média ≥ 68 no questionário SUS (System Usability Scale).
{% endhint %}

</details>

<details>

<summary><strong>RNF02. Desempenho</strong></summary>

* O feedback visual de uma ação deve aparecer em até 1 s.&#x20;
* A navegação entre telas deve responder em até 2 s.

</details>

<details>

<summary><strong>RNF03. Segurança</strong></summary>

* Senhas armazenadas com hash bcrypt.
* Sessão autenticada por token.
* Toda comunicação sob HTTPS.

</details>

<details>

<summary><strong>RNF04. Confiabilidade</strong> </summary>

Uma falha na rotina ou na API de IA não pode travar o sistema. O usuário deve ver uma mensagem que diz o que aconteceu e o que fazer (ex.: tentar de novo, revisar o arquivo), e o erro deve ser registrado no histórico e nos logs.

</details>

<details>

<summary><strong>RNF05. Privacidade</strong> </summary>

Só dados sensíveis e confidenciais não podem ser enviados à API de IA.&#x20;

Os arquivos só podem ser enviados à IA pelos módulos que dependem dela para processar (ex.: Conferência de Fichas), e sempre pela Vertex AI dentro do projeto GCP da empresa. O Informe de IA recebe apenas resumos estruturados.

</details>

<details>

<summary><strong>RNF06. Extensibilidade</strong></summary>

Uma nova rotina deve ser integrada apenas implementando o padrão de módulo (4.2), sem alterar as telas existentes.

</details>

<details>

<summary><strong>RNF07. Compatibilidade</strong></summary>

A interface deve funcionar nos navegadores Chrome e Edge atuais, com prioridade para desktop.

</details>
